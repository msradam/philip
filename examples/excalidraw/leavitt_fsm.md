# From whiteboard to running agent: Leavitt

[Leavitt](https://github.com/msradam/leavitt) is an incident-triage agent
built on Theodosia. It reads Grafana metrics and logs, client-side load,
and deployment context, correlates them, and reports what broke and why.
Leavitt won the [Crusoe + fast-agent + Hermes hackathon prize](https://x.com)
in May 2026. Its FSM is ten states with one retry loop.

This walkthrough lifts the same FSM from a hand-drawn Excalidraw sketch
into an MCP-mountable Burr Application in two function calls. No code
generation, no LLM in the path. The diagram is the contract.

## The sketch

[`leavitt_fsm.excalidraw`](./leavitt_fsm.excalidraw) is a ten-shape
Excalidraw diagram of Leavitt's workflow:

```
  receive_query
       │
       ▼
  enumerate_sources
       │
       ▼
  query_grafana_metrics ◀──┐
       │                    │
       ▼                    │
  query_grafana_logs        │
       │                    │
       ▼                    │ (need_more)
  query_client_load         │
       │                    │
       ▼                    │
  query_deployment_context  │
       │                    │
       ▼                    │
  correlate_evidence ───────┘
       │ (ok)
       ▼
  distill_evidence
       │
       ▼
  form_hypothesis
       │
       ▼
  produce_report
```

The retry edge labeled `need_more` and the forward edge labeled `ok` are
the agent's two choices at the `correlate_evidence` shape. Every other
edge is unconditional.

## The lift

```python
import philip
import theodosia

# Excalidraw -> typed graph -> Burr Application -> MCP server
server = theodosia.mount(
    philip.from_excalidraw("leavitt_fsm.excalidraw").to_burr,
    name="leavitt-from-sketch",
    instructions=(
        "Incident-triage agent walking a workflow drawn in Excalidraw. "
        "At correlate_evidence, set _choice to 'ok' to advance or "
        "'need_more' to loop back and gather more evidence."
    ),
)
server.run()
```

Pipeline:

1. `philip.from_excalidraw(path)` reads the Excalidraw JSON and returns
   a `PhilipGraph` (a typed directed graph: nodes, edges, labels).
2. `.to_burr()` projects the IR onto a runnable Burr Application. The
   retry loop is fine here; Burr accepts cycles. The two outbound
   `correlate_evidence` edges with `ok` and `need_more` labels lift to
   `_choice == "ok"` and `_choice == "need_more"` guards.
3. `theodosia.mount(factory, name, instructions)` wraps the Application
   in a FastMCP server. Every step is audit-trailed; the agent can fork
   from any prior sequence_id for postmortem replay.

## What the agent can and cannot do

The agent connected over MCP can:

- Call `step("receive_query")` to begin
- Call `step("enumerate_sources")` after `receive_query` succeeded
- Walk through the linear collection chain
- At `correlate_evidence`, set `_choice` to either `"ok"` or
  `"need_more"` and step into the matching downstream state

The agent *cannot*:

- Skip from `enumerate_sources` to `produce_report` (no such edge)
- Run `produce_report` before `form_hypothesis` (transition guard fails)
- Loop indefinitely without setting `_choice` (the FSM requires a
  decision at the branching state)
- Invent a state name the diagram doesn't contain

The diagram is the contract. The agent operates within it.

## What this demo is, and what it is not

This example shows the structural lift. The action bodies generated by
`to_burr()` are passthroughs that record state transitions for the
audit trail. The real Leavitt agent at
[github.com/msradam/leavitt](https://github.com/msradam/leavitt) wires
the same FSM to upstream Grafana, flagctx, and load-graph MCP servers
through hand-written action bodies that call into those services.

A complete agent built this way would:

1. Sketch the workflow in Excalidraw (this step)
2. Lift via `from_excalidraw().to_burr()` to get the FSM skeleton
3. Replace each passthrough action with a Python function that calls
   the upstream tool the workflow requires
4. Mount via Theodosia, run

The skeleton-from-sketch step is the part that used to require writing
Burr code by hand. Philip removes that step.

## Composition

This example uses three independent libraries:

- [Philip](https://github.com/msradam/philip) lifts the diagram to a
  Burr Application
- [Burr](https://burr.apache.org/) is the state-machine substrate
- [Theodosia](https://github.com/msradam/theodosia) mounts the
  Application as MCP

None of them depend on the others at package level. Pip install each as
needed.
